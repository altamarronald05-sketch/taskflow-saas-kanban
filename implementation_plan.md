## 🎯 Componentes a Implementar

### 1. 🔐 Supabase Authentication Engine (`supabase.auth`)
- Reemplazo de lógica local por **Supabase Auth Nativo**:
  - `supabase.auth.signUp()`: Registro de usuarios con confirmación e inserción en PostgreSQL.
  - `supabase.auth.signInWithPassword()`: Login seguro mediante tokens JWT administrados por Supabase.
  - `supabase.auth.signOut()`: Cierre de sesión seguro.
  - `supabase.auth.getUser()`: Obtención del perfil activo.

### 2. 🗄️ Esquema de Base de Datos PostgreSQL en la Nube (`schema.sql`)
Crearemos un script SQL listo para ejecutar en el Editor SQL de Supabase con la siguiente estructura:

```sql
-- Creación de la tabla de tareas vinculada a auth.users
CREATE TABLE public.tasks (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE DEFAULT auth.uid(),
    title TEXT NOT NULL,
    description TEXT,
    priority TEXT DEFAULT 'Media',
    category TEXT DEFAULT 'Frontend',
    status TEXT DEFAULT 'todo',
    due_date DATE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Habilitar Row Level Security (RLS)
ALTER TABLE public.tasks ENABLE ROW LEVEL SECURITY;

-- Política de Seguridad: Los usuarios solo pueden ver/modificar sus propias tareas
CREATE POLICY "Users can only access their own tasks" 
ON public.tasks FOR ALL 
USING (auth.uid() = user_id);
```

### 3. ⚙️ Archivo de Configuración de Supabase (`supabaseClient.js`)
- Un cliente modular que inicializa Supabase con tus credenciales: `SUPABASE_URL` y `SUPABASE_ANON_KEY`.
- **Doble Modo (Hybrid Engine)**: Si el usuario configura sus llaves de Supabase, la app se conecta automáticamente a PostgreSQL Cloud; si no, utiliza el servidor Node.js local como respaldo.
